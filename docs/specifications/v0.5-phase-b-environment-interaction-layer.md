# v0.5 Phase B — Environment Interaction Layer implementation specification

## 1. Status

- **Version:** `1.0`
- **Status:** Proposed implementation specification
- **Target:** v0.5 Phase B, simulation-only runtime
- **Architecture authority:** [Environment Interaction Layer](../architecture/environment-interaction-layer.md)
- **Decision record:** [ADR-006](../adr/ADR-006-environment-interaction-layer.md), Proposed
- **Resource dependency:** [Phase A specification](v0.5-phase-a-operational-resource-foundation.md)

Authority descends from the Phase B architecture, ADR-006, this specification,
then implementation and tests. Phase A contracts remain authoritative for
resources. Historical `environment-interface.md` and ADR-004 are non-authoritative.

This specification becomes the authoritative implementation contract for the
Phase B runtime. It permits only deterministic, in-memory simulation. It
prohibits external I/O, live providers, persistence, current pipeline/execution
integration, observations, memory, knowledge, reflection, and autonomous action.

## 2. Design principles

| Principle | Purpose and constraint | Implementation and validation consequence |
|---|---|---|
| Provider neutrality | Preserve semantic intent; provider names and SDK values MUST NOT enter public contracts. | Reject arbitrary/provider objects; adapters contain translation. |
| Semantic operations | Give each interaction stable meaning. | Only the seven `Operation` values and their fixed semantics are valid. |
| Explicit targeting | Make the governed target auditable. | Each request MUST contain exactly one Phase A `ResourceReference`. |
| Deterministic simulation | Make results reproducible. | No clock, randomness, environment, filesystem, network, process, or insertion-order dependence. |
| Default deny | Prevent implicit authority. | An unmatched policy request returns `DENIED`. |
| Least privilege | Prevent scope expansion. | Requested permissions MUST be supported by the descriptor, environment capability, and policy grant. |
| Explicit side effects | Prevent understated risk. | Request intent MUST exactly match the operation mapping. |
| No hidden state | Make composition inspectable. | Registries, policies, approvals, adapters, IDs, and catalogs are explicitly injected. |
| No import discovery | Prevent nondeterministic startup. | Package imports MUST NOT construct or populate services. |
| No secrets | Keep contracts and evidence safe. | Recursive validation rejects secret-shaped keys; adapters MUST sanitize output. |
| Bounded evidence | Prevent payload/log abuse. | Typed evidence has count and size limits. |
| Immutable receipts | Preserve audit integrity. | All public models are frozen and defensively copy nested values. |
| Adapter isolation | Prevent governance bypass. | Adapters only validate support and simulate normalized operations. |
| Mode separation | Prevent real effects. | `LIVE` is modeled but deterministically rejected before adapter invocation. |
| No re-resolution | Preserve Phase A ownership. | The service performs exact catalog lookup only; it MUST NOT create requirements or call `ResourceResolver`. |
| No pipeline change | Preserve current behavior. | Phase B is independently composed and tested; no existing integration changes are permitted. |

be side-effect free.

## 4. Schema version

Every serialized public data contract SHALL carry `schema_version: str = "1.0"`.
Only exact `"1.0"` is accepted. Unsupported versions raise
`EnvironmentValidationError(code=UNSUPPORTED_SCHEMA_VERSION)`. Serialization
uses the string `"1.0"`.

Phase B schema versioning is independent from, but initially equal to, resource
and execution schema `1.0`. Additive optional fields with defaults MAY remain
within 1.x only after specification revision. Removing, renaming, changing
meaning/type, or changing a default requires a new major schema version.

## 5. Identifier model

All identifier strings MUST match ASCII `[A-Za-z0-9._:-]{1,128}` exactly,
retain caller spelling, and be case-sensitive. Whitespace trimming or case
normalization MUST NOT occur. Equality and hashing use stored values. Values
MUST NOT contain paths, hosts, process IDs, credentials, query strings, or
machine-specific data.

`EnvironmentIdentity` is a frozen value object with `namespace: str` and
`environment_id: str`; `key` is `(namespace, environment_id)` and string form is
`namespace:environment_id`. `AdapterIdentity` is frozen with `adapter_id: str`
and `adapter_version: str`; its key is `(adapter_id, adapter_version)`.

`request_id`, `result_id`, `receipt_id`, `correlation_id`, `policy_decision_id`,
and `approval_id` are validated strings using the same rule. They are not
separate wrapper classes. `idempotency_key` uses `[A-Za-z0-9._:-]{8,128}`.
All IDs are caller supplied; the runtime MUST NOT generate them.

## 6. Operation enum

`Operation(str, Enum)` contains exactly:

| Member/value | Semantics | Arguments/output | Permission/idempotency |
|---|---|---|---|
| `READ = "read"` | Retrieve bounded representation of the target | optional read selectors / structured content | `read`; naturally repeatable |
| `LIST = "list"` | Enumerate members of a known collection target | optional cursor/limit / ordered items | `inspect`; naturally repeatable |
| `SEARCH = "search"` | Discover matches using structured criteria | non-empty criteria / ordered matches | `discover`; naturally repeatable for fixed state |
| `CREATE = "create"` | Create one child or derived resource through target context | non-empty proposed fields / created representation or reference | `create`; idempotency key required |
| `UPDATE = "update"` | Change the target | non-empty changes / updated representation or reference | `modify`; idempotency key required |
| `DELETE = "delete"` | Delete or mark target deleted | optional conditions / deletion acknowledgement | `delete`; idempotency key required |
| `EXECUTE = "execute"` | Invoke target-defined bounded computation | non-empty invocation arguments / structured outcome | `execute`; idempotency key required |

All operations are simulation-only in Phase B. `LIST` and `SEARCH` remain
distinct. Adapters MUST NOT redefine their semantics. `OBSERVE`, `NOTIFY`,
`STREAM`, `WATCH`, and `SUBSCRIBE` are invalid.

## 7. Side-effect model

`SideEffectIntent` contains `NONE = "none"`, `READ_ONLY = "read_only"`,
`MUTATING = "mutating"`, `DESTRUCTIVE = "destructive"`, and
`EXECUTING = "executing"`.

The exact operation mapping is:

```text
READ, LIST, SEARCH -> READ_ONLY
CREATE, UPDATE     -> MUTATING
DELETE             -> DESTRUCTIVE
EXECUTE            -> EXECUTING
```

`NONE` is reserved for future non-resource control requests and is incompatible
with every Phase B operation. The request value MUST equal, not merely exceed,
the mapping. Mutation, destruction, and execution always require explicit
policy rules; approval behavior follows section 25. Simulation produces no
actual side effect.

`SideEffectProfile` contains `READ_ONLY`, `MUTATING`, `DESTRUCTIVE`, and
`EXECUTING`, in that increasing support order. An environment profile supports
its level and all lower levels. `NONE` is not an environment profile.

## 8. Execution mode

`ExecutionMode` contains `SIMULATED = "simulated"` and `LIVE = "live"`.
Models can represent both for forward compatibility. The Phase B service
returns `UNSUPPORTED/SIMULATION_ONLY` for every `LIVE` request before resource
lookup or environment resolution. It MUST NOT invoke an adapter.

Definitions, capabilities, and adapters SHALL declare only `SIMULATED` in this
increment. Results and receipts record the requested mode and `simulated:
bool`; `simulated` MUST equal `(execution_mode is SIMULATED)`.
`SIMULATION_ONLY` is a policy outcome/reason, not an execution mode.

## 9. Environment type

`EnvironmentType` contains:

- `DOCUMENT = "document"`: documents/artifacts; read, list, search, create,
  update, delete.
- `REPOSITORY = "repository"`: versioned project resources; all operations.
- `COMMUNICATION = "communication"`: message/channel resources; read, list,
  search, create.
- `KNOWLEDGE = "knowledge"`: governed knowledge collections; read, list, search.
- `COMPUTE = "compute"`: executable/process/model resources; read and execute.
- `SIMULATION = "simulation"`: provider-neutral test contexts; all operations.

Compatibility is declared by each `EnvironmentCapability.supported_resource_types`;
the descriptions above do not create implicit matching. Provider-specific
values are prohibited.

## 10. Trust model

`TrustLevel` contains `UNTRUSTED = "untrusted"`, `CONSTRAINED = "constrained"`,
`TRUSTED = "trusted"`, and `SYSTEM = "system"`, ordered exactly as written.
Minimum-trust matching uses this order. Trust is policy input, never authority.

`EnvironmentLifecycleState` contains `ACTIVE = "active"`,
`UNAVAILABLE = "unavailable"`, `DISABLED = "disabled"`, and
`RETIRED = "retired"`. Only `ACTIVE` resolves. `UNAVAILABLE` contributes an
unavailable outcome; disabled/retired definitions are incompatible.

`SideEffectProfile` is defined in section 7. Enum serialization uses values;
unknown values are rejected.

Frozen `EnvironmentCapability` fields:

| Field | Type/default | Rules |
|---|---|---|
| `schema_version` | `str = "1.0"` | exact |
| `operation` | `Operation` | required |
| `supported_resource_types` | `tuple[str, ...]` | 1–32 unique Phase A identifiers, sorted |
| `supported_execution_modes` | `tuple[ExecutionMode, ...] = (SIMULATED,)` | 1–2 unique, enum order |
| `required_permissions` | `tuple[str, ...] = ()` | 0–32 unique identifiers, sorted; MUST include operation default permission |

Equality includes every field. Hashing is supported after canonical immutable

Frozen fields:

| Field | Type/default | Rules |
|---|---|---|

| `correlation_id` | `str` | identifier |
| `resource_reference` | `ResourceReference` | exactly one |
| `operation` | `Operation` | required |

## 14. Resource targeting

Phase B supports exactly one `resource_reference` per request. This avoids
partial/mixed semantics and makes one receipt correspond to one target.
Collections are targeted as one collection resource for LIST/SEARCH/CREATE.
Multiple targets require multiple requests sharing a correlation ID.

A future major schema may add multi-target requests. Phase B constructors MUST
reject lists/tuples in `resource_reference`.

## 15. Structured arguments

Allowed recursively: `None`, bool, integer, finite float, string, list/tuple,
and string-keyed mapping. Construction canonicalizes sequences to tuples and
mappings to immutable key-sorted mappings. Limits:

- nesting depth: 6, root mapping at depth 0;
- mapping entries: 64 per mapping and 256 total;
- sequence length: 128;
- string length: 4,096 Unicode code points;
- mapping key: `[A-Za-z0-9._:-]{1,64}`;
- canonical compact UTF-8 JSON payload: at most 32,768 bytes.

Binary values, sets, arbitrary objects, enums not explicitly serialized,
dataclasses, callables, NaN, infinities, recursive structures, duplicate JSON
keys, and secret-shaped keys are rejected. JSON key ordering is lexical.
Adapters MUST NOT relax these limits.

## 16. Environment constraints

Frozen `EnvironmentConstraints` fields:

| Field | Type/default | Semantics |
|---|---|---|
| `preferred_environment_identity` | `EnvironmentIdentity | None` | preference only |
| `required_environment_type` | `EnvironmentType | None` | required |
| `minimum_trust_level` | `TrustLevel | None` | required ordered minimum |
| `required_execution_mode` | `ExecutionMode | None` | required and MUST equal request mode |
| `required_lifecycle_state` | `EnvironmentLifecycleState = ACTIVE` | required |
| `allowed_adapter_identities` | tuple of `AdapterIdentity` | empty means unrestricted |
| `forbidden_adapter_identities` | tuple | hard exclusion |
| `policy_profile` | `str | None` | exact required match |

Required fields combine with AND. Allowed/forbidden overlap is invalid.
Non-ACTIVE required lifecycle is valid but resolves unavailable/incompatible
according to section 23. Collections are unique/canonically sorted.
Evaluation order is the field order above, except preference scoring occurs
after all hard filters. Unknown fields cannot be constructed.

## 17. EnvironmentResult

`ResultStatus` contains `SUCCESS`, `DENIED`, `APPROVAL_REQUIRED`, `UNSUPPORTED`,
`UNAVAILABLE`, `INVALID_REQUEST`, `TIMEOUT`, `CONFLICT`, `ADAPTER_FAILURE`, and
`INTERNAL_ERROR`, serialized lowercase. `PARTIAL` is prohibited.
Simulation is the boolean `simulated`, not a status.

Frozen fields: `schema_version`, `result_id`, `request_id`, `correlation_id`,
`environment_identity: EnvironmentIdentity | None`,
`adapter_identity: AdapterIdentity | None`, `execution_mode`, `status`,
`reason_code: ReasonCode`, `output` (safe structured mapping),
`returned_resource_references: tuple[ResourceReference, ...]`,
`evidence: tuple[EvidenceEntry, ...]`, `safe_message: str`,
`simulated: bool`, and `metadata`.

`safe_message` is 0–512 characters. Output is ≤32 KiB and returned references
are ≤16, unique and canonically ordered. `SUCCESS` requires a selected
environment/adapter, `ReasonCode.SUCCESS`, and may contain output/references.
All failure statuses require empty output and references. Status/reason pairs
MUST follow section 18. `simulated` matches execution mode. Adapter-returned
results MUST be SUCCESS in Phase B; service-generated early exits carry other
statuses.

`EnvironmentErrorCode(str, Enum)` contains:
`UNSUPPORTED_SCHEMA_VERSION`, `INVALID_IDENTIFIER`, `INVALID_CONTRACT`,
`INVALID_ARGUMENTS`, `SECRET_MATERIAL`, `DUPLICATE_ENVIRONMENT`,
`DUPLICATE_ADAPTER`, `MISSING_ENVIRONMENT`, `MISSING_ADAPTER`,
`INVALID_ENVIRONMENT_DEFINITION`, `INVALID_ADAPTER_DECLARATION`,

`EnvironmentDomainError(ValueError)` exposes immutable `code` and `message`.
Subclasses are `EnvironmentValidationError`,
`EnvironmentRegistrationError`, `EnvironmentAdapterError`, and
`EnvironmentInvariantError`. Messages MUST be safe and contain no rejected

## 20. Adapter protocol

Use `typing.Protocol` with `@runtime_checkable`, synchronous and simulation-only:

```python
class EnvironmentAdapter(Protocol):
    @property
    def adapter_identity(self) -> AdapterIdentity: ...

    @property
    def supported_environment_types(self) -> tuple[EnvironmentType, ...]: ...

    @property
    def supported_execution_modes(self) -> tuple[ExecutionMode, ...]: ...

    @property
    def supported_operations(self) -> tuple[Operation, ...]: ...

    def validate_request(
        self,
        request: EnvironmentRequest,
        environment: EnvironmentDefinition,
        resource: ResourceDescriptor,
    ) -> None: ...

    def supports(
        self,
        request: EnvironmentRequest,
        environment: EnvironmentDefinition,
        resource: ResourceDescriptor,
    ) -> bool: ...

    def simulate(
        self,
        request: EnvironmentRequest,
        environment: EnvironmentDefinition,
        resource: ResourceDescriptor,
        *,
        result_id: str,
    ) -> EnvironmentResult: ...
```

Version is part of `AdapterIdentity`. No `execute()` method exists. Adapters
MUST NOT select/resolve resources, evaluate policy/approval, mutate registry,
perform I/O, access secrets, or return provider objects.

## 21. Simulated adapter

Implement exactly one `GenericSimulationAdapter`. Its identity is caller
supplied at construction; canonical tests use
`AdapterIdentity("adapter:generic-simulation", "1.0")`. It declares all six
environment types, `SIMULATED`, and all seven operations.

`supports` returns true only when mode/type/operation and bound environment
capability match. `validate_request` raises `EnvironmentAdapterError` for a
support mismatch. `simulate` returns SUCCESS with:

```json
{
  "operation": "<operation value>",
  "request_id": "<request id>",
  "resource": {
    "namespace": "<namespace>",
    "resource_id": "<resource id>",
    "version": "<version or null>",
    "revision": "<revision or null>"
  },
  "simulated": true
}
```

Keys have lexical canonical serialization. Returned references are empty and
evidence contains one ADAPTER entry. Failure injection is prohibited; tests
use deliberately malformed protocol implementations for failure paths. The
adapter uses no time, random, filesystem, network, environment, or process
state.

## 22. Environment registry

Use one instance-owned `EnvironmentRegistry` for both definitions and adapter
instances. Constructor accepts optional iterables and registers them through
the public methods:

```python
register_adapter(adapter: EnvironmentAdapter) -> None
register_environment(definition: EnvironmentDefinition) -> None
get_adapter(identity: AdapterIdentity) -> EnvironmentAdapter
get_environment(identity: EnvironmentIdentity) -> EnvironmentDefinition
list_adapters() -> tuple[EnvironmentAdapter, ...]
list_environments() -> tuple[EnvironmentDefinition, ...]
seal() -> None
```

Adapters MUST be registered before bound environments. Duplicate keys raise
registration errors even for equal objects. Lists sort adapters by
`(adapter_id, adapter_version)` and environments by `(namespace,
environment_id)`. `seal` is irreversible and causes later registration to
raise `EnvironmentRegistrationError(INTERNAL_INVARIANT)`; lookup remains valid.
The service requires a sealed registry, preventing mutation during resolution.
Constructor inputs are copied. No singleton, discovery, population, clone
sharing, or thread synchronization exists.

## 23. Environment resolver

`EnvironmentResolver.resolve(request, resource, registry) ->
EnvironmentResolution` performs:

1. validate argument types;
2. enumerate canonical environment list;
3. record non-ACTIVE lifecycle;
4. filter required environment type;
5. filter request/constraint execution mode;
6. filter resource `type_id` against capability resource types;
7. filter operation capability;
8. filter environment side-effect support;
9. filter requested permissions against both resource descriptor and capability;
10. apply required constraints in section 16 order;
11. verify bound registered adapter and adapter declaration support;
12. score preferred identity (`1` match, otherwise `0`);
13. sort by `(-preference_score, namespace, environment_id, adapter_id,
    adapter_version)`;
14. if two eligible candidates share the highest preference score, return
    ambiguous;
15. otherwise select the first candidate.

`EnvironmentResolution` is frozen with `request_id`, `status:
EnvironmentResolutionStatus`, selected environment/adapter identities or
`None`, `reason_code`, and ordered evidence. Status values are `RESOLVED`,
`AMBIGUOUS`, `UNSUPPORTED`, and `UNAVAILABLE`.

No-match classification uses evidence precedence:
adapter unavailable; environment unavailable; unsupported operation;
incompatible resource; no compatible environment. Evidence is bounded to one
entry per environment plus one summary, maximum 101. Registry bounds prevent
overflow. No adaptive ranking, clock, random, insertion order, or I/O.

## 24. Policy

`PolicyOutcome` contains `ALLOW`, `DENY`, `REQUIRE_APPROVAL`,
`SIMULATION_ONLY`, and `UNSUPPORTED`, serialized lowercase.

Frozen `PolicyRule` fields: `rule_id`, `actor_id`, `operation`,
`environment_identity`, `resource_namespace`, `resource_id`,
`execution_mode`, `granted_permissions`, and `outcome`. Every match is exact;
grants are a subset of requested permissions.

Frozen `PolicyDecision` fields: `schema_version`, `decision_id`, `request_id`,
`policy_id`, `policy_version`, `outcome`, `granted_permissions`,
`reason_code`, and evidence.

Protocol:

```python
class PolicyEvaluator(Protocol):
    def evaluate(
        self,
        request: EnvironmentRequest,
        resource: ResourceDescriptor,
        environment: EnvironmentDefinition,
        *,
        decision_id: str,
    ) -> PolicyDecision: ...
```

`StaticPolicyEvaluator(policy_id, policy_version, rules)` copies and
canonically sorts rules by `rule_id`. Zero or multiple matching rules return
DENY/POLICY_DENIED; exactly one produces its outcome. `LIVE` always produces
SIMULATION_ONLY regardless of rules. ALLOW/REQUIRE_APPROVAL require grants to
equal all requested permissions; otherwise DENY. Resource permissions are a
descriptive prerequisite already checked by the resolver, not authorization.
Reason mapping is exact: ALLOW uses SUCCESS, DENY uses POLICY_DENIED,
REQUIRE_APPROVAL uses APPROVAL_REQUIRED, SIMULATION_ONLY uses SIMULATION_ONLY,
and UNSUPPORTED uses UNSUPPORTED_OPERATION.

## 25. Approval

`ApprovalStatus` contains `GRANTED`, `MISSING`, `EXPIRED`, and
`SCOPE_MISMATCH`. Frozen `ApprovalGrant` fields are `approval_id`,
`approver_id`, `request_id`, `policy_id`, `policy_version`, `operation`,
`resource_reference`, `environment_identity`, `granted_permissions`,
`valid_from_epoch_ms`, `expires_at_epoch_ms`, and `reusable: bool = False`.
Times are caller-supplied logical epoch values; expiration evaluation receives
an explicit `evaluation_epoch_ms`.

Frozen `ApprovalDecision` contains `schema_version`, `approval_id: str | None`,
`request_id`, `status`, `approver_id: str | None`, `reason_code`, and evidence.

Protocol:

```python
class ApprovalEvaluator(Protocol):
    def evaluate(
        self,
        request: EnvironmentRequest,
        resource: ResourceDescriptor,
        environment: EnvironmentDefinition,
        policy_decision: PolicyDecision,
        *,
        evaluation_epoch_ms: int,
    ) -> ApprovalDecision: ...
```

`ExplicitApprovalEvaluator(grants)` copies grants and matches exact request,
policy/version, operation, reference, environment, and permissions. Evaluation
order is exact match, time validity, then scope. No candidate means MISSING;
expired exact candidate means EXPIRED; a request-bound candidate with other
scope mismatch means SCOPE_MISMATCH; exactly one valid match means GRANTED.
Multiple valid matches are an invariant error. Grants are not consumed;
`reusable` is descriptive because persistence is deferred. Approval is skipped
for ALLOW and cannot override DENY/SIMULATION_ONLY/UNSUPPORTED.
Epoch fields are non-boolean integers from 0 through `2**63 - 1`, expiry MUST
be greater than validity start, and evaluation time uses the same bounds.

## 26. Lifecycle service

`EnvironmentInteractionService` constructor requires a `ResourceCatalog`,
sealed `EnvironmentRegistry`, `EnvironmentResolver`, `PolicyEvaluator`, and
`ApprovalEvaluator`. It constructs none implicitly.

Public method:

```python
interact(
    request: EnvironmentRequest,
    *,
    result_id: str,
    receipt_id: str,
    policy_decision_id: str,
    evaluation_epoch_ms: int = 0,
) -> InteractionOutcome
```

`InteractionOutcome` is frozen with exactly `result: EnvironmentResult` and
`receipt: InteractionReceipt`.

Order:

1. validate method inputs and identifiers;
2. reject LIVE;
3. exact resource-reference validation;
4. resolve environment;
5. return result/receipt for unresolved resolution;
6. evaluate policy;
7. return denial/unsupported/simulation-only receipt;
8. evaluate approval only for REQUIRE_APPROVAL;
9. return approval-required receipt unless granted;
10. validate adapter request;
11. simulate adapter;
12. validate and normalize adapter result;
13. merge ordered evidence;
14. construct receipt;
15. return outcome.

Every expected early exit returns an outcome and receipt. Contract/programmer
errors before an interaction can be safely represented raise domain errors.

## 27. Resource validation

The service receives an explicit Phase A `ResourceCatalog` and calls only
`catalog.get(reference)`. It MUST NOT call `catalog.resolve`, construct a
requirement, select an alternate version, or mutate the catalog.

- missing identity/version/revision: INVALID_REQUEST/INVALID_REFERENCE;
- descriptor status STALE: INVALID_REQUEST/STALE_REFERENCE;
- ARCHIVED or DELETED: INVALID_REQUEST/STALE_REFERENCE;
- RESTRICTED: DENIED/RESOURCE_RESTRICTED;
- UNAVAILABLE: UNAVAILABLE/ENVIRONMENT_UNAVAILABLE;
- DECLARED or AVAILABLE: continue;
- descriptor/type mismatch with environment: resolver INCOMPATIBLE_RESOURCE;
- requested permission absent from descriptor: resolver INCOMPATIBLE_RESOURCE.

Schema compatibility is enforced by Phase A constructors. Returned references
are validated structurally but are not registered or resolved.

## 28. Interaction receipt

Frozen `InteractionReceipt` fields:

`schema_version`, `receipt_id`, `request_id`, `result_id`, `correlation_id`,
`environment_identity: EnvironmentIdentity | None`,
`adapter_identity: AdapterIdentity | None`, `resource_reference`, `operation`,
`execution_mode`, `simulated`, `policy_summary: PolicySummary | None`,
`approval_summary: ApprovalSummary | None`, `status`, `reason_code`, `evidence`,
`idempotency_key_digest: str | None`, `execution_receipt_reference: str | None`,
and safe metadata.

`PolicySummary` contains decision ID, policy ID/version, outcome, granted
permissions, and reason. `ApprovalSummary` contains approval ID, approver ID,
status, and reason. Summaries are frozen.

No timestamps are stored. Every field participates in equality. Hashing is
supported. If present, idempotency digest is lowercase SHA-256 hex computed
from UTF-8 key; the key itself is never retained. Execution receipt reference
is `None` in Phase B. Evidence is 1–128 entries. Receipt/result status,
reason, IDs, mode, and simulation MUST match.

## 29. Evidence model

`EvidenceStage` contains `RESOLUTION`, `POLICY`, `APPROVAL`, `ADAPTER`,
`NORMALIZATION`, and `RECEIPT`, serialized lowercase and ordered as listed.

Frozen `EvidenceEntry` fields: `stage`, `sequence: int`, `summary: str`,
`reason_code: ReasonCode`, `related_identifier: str | None`, and safe metadata.
Sequence is contiguous from 1 in a final outcome. Summary is 1–256 characters;
metadata is ≤16 entries/4 KiB; entries are ≤128; total serialized evidence is
≤32 KiB. Identifiers may expose only AEGIS contract identities, never locators,
credentials, provider IDs, or descriptors.

Each stage appends in lifecycle order. Within resolution, candidate entries
use canonical environment order. The service resequences merged evidence and
adds exactly one RECEIPT entry last. Free-form logs are not evidence.

## 30. Correlation

Callers supply every ID. The service generates none. The request correlation
ID propagates unchanged to result and receipt. Result and receipt contain the
originating request ID; receipt contains the result ID. One receipt maps to
exactly one request/result/target. `execution_receipt_reference` remains `None`.

Duplicate request IDs are not detected because no service ledger exists.
Deterministic tests supply fixed distinct IDs. IDs are safe serialized strings.

## 31. Idempotency

Idempotency is declarative in Phase B; there is no ledger, cache, replay
detection, or persistence. Keys are prohibited for READ/LIST/SEARCH and
required for CREATE/UPDATE/DELETE/EXECUTE. The adapter's deterministic
simulation means identical complete inputs produce identical output, but the
service does not guarantee exactly-once processing.

`IDEMPOTENCY_CONFLICT` is reserved and MUST NOT be emitted by the first
runtime. Receipts retain only the SHA-256 digest.

## 32. Timeout model

`timeout_ms` is an integer number of milliseconds from 1 through 300,000;
booleans are invalid. It serializes as an integer. Phase B validates but does
not enforce elapsed time and never reads a clock. `TIMEOUT` is reserved for a
future adapter; `GenericSimulationAdapter` never returns it.

## 33. Partial results

Partial completion is deferred. `ResultStatus.PARTIAL` does not exist,
capabilities MUST set `supports_partial_results=False`, and adapter results
containing partial markers or mixed successful/failed subsets are malformed.
Multi-resource requests are also prohibited.

## 34. Failure precedence

The service applies this strict precedence:

| Rank | Outcome |
|---:|---|
| 1 | Invalid method/contract input raises validation error; representable invalid request returns INVALID_REQUEST |
| 2 | LIVE request → UNSUPPORTED/SIMULATION_ONLY |
| 3 | Missing/invalid exact reference → INVALID_REQUEST/INVALID_REFERENCE |
| 4 | Stale/deleted/archived reference → INVALID_REQUEST/STALE_REFERENCE |
| 5 | Restricted resource → DENIED/RESOURCE_RESTRICTED |
| 6 | Unavailable resource → UNAVAILABLE |
| 7 | Ambiguous eligible environments → CONFLICT |
| 8 | Compatible environment with unavailable/missing adapter → UNAVAILABLE/ADAPTER_UNAVAILABLE |
| 9 | Otherwise compatible but unavailable environment → UNAVAILABLE/ENVIRONMENT_UNAVAILABLE |
| 10 | Unsupported operation |
| 11 | Incompatible resource |
| 12 | No compatible environment |
| 13 | Policy UNSUPPORTED or SIMULATION_ONLY |
| 14 | Policy DENIED |
| 15 | Approval scope mismatch |
| 16 | Approval expired |
| 17 | Approval missing/required |
| 18 | Adapter validation failure → ADAPTER_FAILURE |
| 19 | Adapter exception → ADAPTER_FAILURE |
| 20 | Malformed adapter result raises `EnvironmentAdapterError` |
| 21 | Timeout (reserved) |
| 22 | Partial completion raises `EnvironmentAdapterError` |
| 23 | Internal invariant violation raises `EnvironmentInvariantError` |

Earlier lifecycle ranks win because later stages are not evaluated. Within
resolver no-match evidence, the classification order in section 23 applies.
Simulation mismatch (LIVE) precedes policy. Malformed returned data raises
before an adapter's claimed failure status can be accepted because adapters may
return SUCCESS only.

## 35. Deterministic output rules

Equal explicit catalog, sealed registry, request, IDs, policy rules, approval
grants/evaluation time, and adapter configuration SHALL produce equal
resolution, policy/approval decisions, evidence, result, receipt, and
`to_dict()` serialization.

Ordering follows defined enum order or canonical keys; mappings serialize by
lexical key; sets are prohibited. No field is excluded from equality. There is
no current time or generated ID. Hash iteration, object address, registration
order, filesystem, network, environment variables, locale, timezone, process,
and randomness MUST NOT affect output.

## 36. Serialization and immutability

Use standard-library frozen dataclasses, matching Phase A. Public models expose
`to_dict() -> dict[str, Any]`; enums serialize to values, tuples to JSON lists,
and nested contracts recursively. Dict insertion order in `to_dict` follows
field declaration; nested mapping keys are lexical. Canonical JSON for bounds
uses UTF-8, `sort_keys=True`, compact separators, and `allow_nan=False`.

Constructors reject unknown fields naturally. Inputs are defensively deep
copied into immutable structures. The private `_FrozenMapping` implements
`collections.abc.Mapping`, stores a tuple of lexically key-sorted `(str,
frozen_value)` pairs, and hashes that tuple. Lists/tuples become tuples;
mappings become `_FrozenMapping`; scalars remain scalars. `to_dict` returns new
mutable dictionaries/lists.
Equality is structural; every public model is hashable. `repr` is dataclass
repr after secret validation and therefore safe. Unsupported schema versions
are rejected.

## 37. Secret and untrusted-data controls

Normalize keys for inspection by lowercasing and removing `-`, `_`, `.`, and
spaces. Reject a key if the normalized form equals or contains:
`password`, `passwd`, `secret`, `token`, `accesstoken`, `refreshtoken`,
`authorization`, `apikey`, `privatekey`, `credentials`, `cookie`, `session`,
or `bearer`. Scan every nested mapping through the maximum allowed depth.

This intentionally favors false positives; callers MUST use opaque safe
reference keys such as `credential_reference_id` only in a future revised
schema—Phase B accepts no credential references. Values are not scanned for
secret words because content cannot be reliably classified; instead all
strings remain bounded and adapters MUST exclude/redact secret data.

Safe errors identify the field path but never echo a value. Limits are:
arguments/output 32 KiB each; general metadata 32 entries/8 KiB; evidence
metadata 16 entries/4 KiB; evidence total 32 KiB; full result or receipt
serialized form 96 KiB. Adapter output is recursively validated before
acceptance. Returned untrusted content remains data and MUST NOT be interpreted,
prompted, executed, or promoted by the interaction layer.

## 42. Performance constraints

- registered environments: maximum 100;
- registered adapters: maximum 32;
- capabilities per environment: maximum 64;
- resource references per request: exactly 1;
- arguments/output: 32 KiB each;
- metadata: 32 entries and 8 KiB per general contract;
- evidence: 128 entries and 32 KiB total;
- serialized result/receipt: 96 KiB each.

Registration rejects exceeding bounds. Resolver complexity is
`O(E log E + E*C)` for environments `E` and capabilities `C`, within the
declared limits. No cache or index is required. Implementations SHOULD avoid
re-copying already immutable values in hot loops, but correctness and isolation
take precedence. Caching MUST NOT affect outputs.

## 43. Compatibility and migration

Phase B imports Phase A public contracts without modifying them. Exact
`ResourceReference` lookup preserves Phase A identity/version/revision
semantics. Phase B schema changes follow section 4; readers reject unsupported
versions rather than guessing. Historical requests/receipts retain their
schema value and require a matching reader.

Future live execution adds adapters and policy, not cognition/provider fields.
Async adapters require a new service/protocol version. External policy engines
may replace `StaticPolicyEvaluator` behind the protocol. Persistent approvals
may replace the evaluator while preserving decision contracts. Execution
integration is additive and separately specified.
